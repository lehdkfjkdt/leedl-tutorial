RL Navigation Policy 增强路线图

从 NavRL 的“Policy + Safety Shield”，到 SEA-Nav、VOP-Nav、ABS/BAS、REASAN 与预测/风险建模：一张图看懂 RL 避障如何继续演化

主线：NavRL → Safety / Prediction / Memory / Risk / Sampling 关注接口：感知 → RL Policy → [vx, vy, ωyaw] → 低层运动控制

核心结论：近两年的改进重点已经不再只是“换一个 PPO / Actor”，而是在 RL Policy 周围增加安全先验、未来预测、风险判断、时序记忆和高价值危险样本。NavRL 是一个强基线；SEA-Nav、VOP-Nav、ABS/BAS、REASAN 等工作，本质上是在不同位置补齐它的短板。

01先看 NavRL：为什么它这么适合作为 Base

NavRL 的接口非常干净：上层感知与目标信息进入 RL Policy，Policy 输出速度命令，再由安全模块做最终过滤。对于四足机器人，这种结构很容易迁移成 [vx, vy, ωyaw] 的“具身小脑”接口。

为什么 NavRL(2T) 看起来特别强

2T 不是新模型，而是给 NavRL 两倍 episode 时间。这说明 NavRL 的典型问题不是完全不会避障，而是更容易“安全但保守”，在复杂场景中可能用更长时间才完成任务。因此后续工作往往围绕“如何在不牺牲安全的前提下更早预判、更敢走、更少冻结”来做增强。

04VOP-Nav 为什么很值得关注：从“预测障碍”转向“预测动作风险”

传统动态避障链路通常很长：检测人 → 跟踪人 → 估计速度 → 预测未来轨迹 → 再做 VO/MPC。VOP-Nav 的关键转变是：不一定要把每个人未来在哪预测得很准，只需要预测哪些速度对机器人来说是危险的。

未来预测不一定要预测“世界本身”，也可以直接预测“对动作决策有用的量”。典型选择包括：未来安全速度区域、未来 collision risk map、未来 latent state。对于具身小脑，这往往比完整 reconstruct 世界更轻、更直接。

SEA-Nav 的价值不只是“把 CBF 换成可导版本”，更重要的是同时处理了三个问题：安全约束如何进入训练、危险动作如何被 Policy 自己学会避免、以及危险区域样本如何更高效地采到。

与 CBF/VO 的根本差异

VO / CBF 把“安全”写成几何或控制规则；REASAN 则让另一个 Policy 自己从大量交互中学会修正危险动作。它更灵活，但也意味着 Safety 本身不再是一个显式数学约束。

09训练数据本身：为什么“高质量危险样本”越来越重要

很多 RL 避障失败，并不是 Policy 容量不够，而是训练中真正危险的状态出现概率太低。于是近年的另一个趋势是：专门设计危险状态采样。

SEA-Nav · ACSI Critical Replay

碰撞或接近碰撞后，不是随机重置，而是回到碰撞前的高价值状态重复练习。

Hi-QARL Adversarial

让动态障碍自己成为对手，通过 curriculum 从“弱敌人”逐渐升级到“会主动堵你/撞你”的强敌人。

传统随机障碍 Baseline

实现简单，但大量样本其实是低风险、低信息量状态，学习效率有限。

11对“感知在环 RL 小脑”的推荐组合

如果目标是：输入多帧 Ray/LiDAR + Robot State + Goal，输出 [vx, vy, ωyaw]，同时兼顾动态避障与复杂场景，我更推荐把“预测、RL、安全约束、危险采样”视为四个互补层，而不是四选一。

Multi-frame Ray / LiDAR
        ↓
Spatio-temporal Encoder
        ↓
Future Risk / Safe Velocity Prediction   ← VOP-Nav / SRU-WM
        ↓
Navigation RL Policy
        ↓
Differentiable Safety Constraint         ← SEA-Nav
        ↓
[vx, vy, ωyaw]
        ↓
Low-level Locomotion

Training:
+ Critical State Replay                  ← SEA-Nav ACSI
+ Dynamic Obstacle Curriculum            ← Hi-QARL
为什么这个组合比“再加一个 CBF”更有研究价值

VOP 类模块解决“提前看见危险”；SEA-Nav 类安全层解决“最终动作不要越过安全边界”；ACSI/Hi-QARL 解决“训练时到底有没有真正见过危险”。三个模块针对的是三个不同瓶颈，因此可以组合，而不是相互替代。
