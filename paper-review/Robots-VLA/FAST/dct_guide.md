# DCT（离散余弦变换）详解：从信号处理到机器人动作压缩

> **用途**：理解 FAST tokenizer 中 DCT 的工作原理
> **关联文档**：[π₀-FAST 论文导读](./fast_paper_guide.md)

## 读之前先搞清楚

### DCT 在做什么？

DCT 回答一个看似简单的问题：**"这段信号由哪些频率的余弦波叠加而成？"**

你听到的任何声音——钢琴、人声、汽车引擎——都可以分解为不同频率的纯音的叠加。DCT 就是做这个分解：输入一段信号（比如 50 步的关节角度序列），输出一组系数——每个系数告诉你"这个频率的成分有多强"。

> **小白理解**：DCT 像给一段波形做"X 光透视"。表面上看是复杂起伏的曲线，透视后发现在骨骼层面只是"一个常数 + 一个缓慢趋势 + 一点高频抖动"。**你不必记住曲线上每个点——记住这几个"骨骼成分"的参数就够了。**

### 阅读本文需要的前置知识

| 概念 | 简单解释 |
|:---|:---|
| **余弦函数 cos(x)** | 一个在 [-1, 1] 之间周期波动的平滑曲线 |
| **频率** | 波动的快慢——低频=缓慢起伏，高频=快速振荡 |
| **正交基** | 一组"互不干扰"的基础信号——就像 x 轴和 y 轴是平面上互不干扰的两个方向 |
| **变换** | 把同一个东西换一种方式表示——比如把"每秒的角度值"换成"每种频率的强度" |

## 一、DCT 的直觉理解

### 1.1 从最简单的例子开始

假设你有一个 4 步的动作序列（单关节）：

```
a = [1.0, 2.0, 3.0, 4.0]   ← 关节角从 1° 匀速增到 4°
```

DCT 问：这 4 个点，用哪 4 个"基础波形"可以完全表示？

```
N=4 的 DCT 基础波形（余弦基）:

  基 0 (k=0): [1,  1,  1,  1]   ← 直流分量，代表"平均高度"
  基 1 (k=1): [cos(π/8), cos(3π/8), cos(5π/8), cos(7π/8)]
             ≈ [0.92, 0.38, -0.38, -0.92]   ← 最低频，半个周期的余弦
  基 2 (k=2): [cos(2π/8), cos(6π/8), cos(10π/8), cos(14π/8)]
             ≈ [0.71, -0.71, -0.71, 0.71]   ← 一个完整周期
  基 3 (k=3): [cos(3π/8), cos(9π/8), cos(15π/8), cos(21π/8)]
             ≈ [0.38, -0.92, 0.92, -0.38]   ← 最高频，快速振荡
```

DCT 系数 $X_k$ = "原信号在基 k 上的投影" = "基 k 在这个信号中的贡献有多大"。

### 1.2 对 [1, 2, 3, 4] 做 DCT

用公式计算四个系数：

| k | DCT 系数 $X_k$ | 含义 |
|:---:|:---:|:---|
| 0 | **5.00** | 平均值——所有点的中心位置 |
| 1 | **-2.23** | 趋势——从 1 到 4 的单调递增趋势很强 |
| 2 | **0.00** | 没有对称的加速/减速 |
| 3 | **-0.16** | 只有极微小的高频噪声 |

> **关键观察**：前两个系数（5.00, -2.23）已经捕获了几乎所有信息。系数 2 和 3 几乎为零。**这就是 DCT 的"能量集中"特性——重要信息挤在前几个低频系数里。**

### 1.3 反变换：从系数重建原信号

逆 DCT（IDCT）从系数重建信号——用系数加权每个基波形，再求和：

```
重建: a_recon[n] = (1/2)·X_0·基0[n] + X_1·基1[n] + X_2·基2[n] + X_3·基3[n]

  只保留前 2 个系数 (X_0=5.0, X_1=-2.23, X_2=0, X_3=0):
    a_recon ≈ [1.02, 1.95, 3.05, 3.98]
    
  原始:     [1.00, 2.00, 3.00, 4.00]
  重建:     [1.02, 1.95, 3.05, 3.98]
  偏差:     [0.02, 0.05, 0.05, 0.02]
```

**只用了 2 个系数（4 个点 → 2 个系数，压缩比 2:1），重建误差 < 0.05！**

如果保留全部 4 个系数，IDCT 能**精确无误**重建原始信号——DCT 本身是无损的。损失发生在后面的量化步骤。

## 二、DCT 的数学定义

### 2.1 一维 DCT-II（最常用的变体）

对长度为 N 的信号 $a_0, a_1, ..., a_{N-1}$，DCT-II 系数为：

$$X_k = \sum_{n=0}^{N-1} a_n \cdot \cos\left[\frac{\pi}{N}\left(n + \frac{1}{2}\right)k\right], \quad k = 0, 1, ..., N-1$$

**逐项解释**：

| 符号 | 含义 |
|:---|:---|
| $X_k$ | 第 k 个 DCT 系数——"频率 k 有多强" |
| $a_n$ | 原始信号的第 n 个值 |
| $\cos[\cdots]$ | 余弦基函数——频率为 k 的余弦波在第 n 个位置上的值 |
| $k=0$ | 直流分量——所有值的加权和，正比于平均值 |
| $k=N-1$ | 最高频分量——相邻点正负交替，代表噪声级变化 |

### 2.2 逆变换（IDCT）

$$a_n = \frac{1}{2}X_0 + \sum_{k=1}^{N-1} X_k \cdot \cos\left[\frac{\pi}{N}\left(n + \frac{1}{2}\right)k\right], \quad n = 0, 1, ..., N-1$$

注意 $X_0$ 前的系数是 $\frac{1}{2}$——这是 DCT-II 的惯例，使正变换和逆变换的形式对称。

## 三、为什么是 DCT？——和 FFT、PCA 的对比

| | DCT | FFT | PCA |
|:---|:---|:---|:---|
| **输出类型** | 实数 | 复数 | 实数 |
| **基函数** | 固定的余弦函数 | 固定的正弦+余弦函数 | 从数据中学习 |
| **能量集中** | ≈ 最优（接近 KL 变换） | 次优（有 Gibbs 效应） | 最优（但需训练） |
| **跨数据集泛化** | ✅ 天然泛化 | ✅ 天然泛化 | ❌ 基依赖于训练数据 |
| **计算复杂度** | O(N log N) | O(N log N) | O(N²)（需特征分解） |
| **典型应用** | JPEG, MP3, FAST | 频谱分析, 通信 | 数据降维, 特征提取 |

**DCT 的四个关键优势**：

1. **实数输出**：FFT 产生复数——幅度和相位。机器人动作只需要实数值。DCT 只有实数系数，直接喂给量化步骤
2. **能量集中效率**：在 Markov-1 信号模型下（机器人运动近似满足），DCT 接近理论上最优的 KL 变换（Karhunen-Loève Transform）
3. **固定基 = 零学习成本**：PCA 需要从数据学基向量——不同数据集学出的基不同，泛化差。DCT 的基是固定的余弦函数，天然跨数据集泛化
4. **快速算法**：有 O(N log N) 的快速 DCT 算法（类似 FFT），计算效率高

> **小白理解**：FFT 像用"正弦+余弦"两个数描述每个频率——信息是复数的（有大小和方向），对信号分析有用但对压缩太冗余。DCT 只用余弦——因为余弦在边界处自然平滑，避免了 FFT 的"边界跳跃"伪影（Gibbs 效应）。**DCT 是 FFT 的更简洁、更实用的版本。**

## 四、DCT 在实际中的应用

### 4.1 JPEG 图像压缩（2D DCT）

JPEG 将图像切成 8×8 像素块，对每个块做 2D DCT：

```
8×8 像素块 → 2D DCT → 8×8 频率系数矩阵
  左上角（低频）: 大数值，代表块的大致颜色和渐变
  右下角（高频）: 接近零，代表细节纹理
  → 量化右下角（高频归零），保留左上角
  → 压缩比通常 10:1 到 20:1
```

### 4.2 MP3 音频压缩（改进的 DCT：MDCT）

MP3 用改进的 DCT（MDCT）将音频切成短时窗，每个窗做频域变换——丢掉人耳听不到的频率。

### 4.3 FAST 动作压缩（1D DCT，每维独立）

FAST 对 action chunk 的**每个维度独立**做 1D DCT：

```
50 步 × 32 维 → 每维做 1D DCT (50 点 → 50 个频率系数)
  → 32 个维度，32 个独立的 DCT
  → 每个维度的前几个低频系数保留，后面的归零
  → 跨维度不混合（不同关节运动模式不同）
```

> 📖 具体的 FAST Tokenizer 管道详见 [π₀-FAST 论文导读](./fast_paper_guide.md)。

## 五、DCT 在 FAST 中的关键设计决策

### 5.1 为什么每维独立做 1D DCT，而不是整个 chunk 做 2D DCT？

2D DCT 会混合不同关节的信息——但腕关节的高频旋转和肩关节的低频平移是完全不同的物理过程，混合后反而产生无意义的耦合系数。

**FAST 的设计**：只压缩时间冗余（同一个关节运动中相邻步的相似性），不压缩空间冗余（不同关节之间的相关性——这个留给 BPE 去发现）。这是一个精心拆分的分工：**DCT 处理时间压缩，BPE 处理空间压缩。**

### 5.2 为什么只保留前几个系数——不会丢精度吗？

回头看 1.3 节的例子：4 个点只用 2 个系数就重建到偏差 < 0.05。机器人的控制精度通常在 ~1mm / ~1° 级别——DCT 保留前 20-30% 的系数，重建误差远小于控制精度。

论文实验也证实：FAST 压缩后的动作在灵巧任务（叠衣、装袋等）上的表现和原始 Flow Matching 相当——说明量化损失在实际任务中不可感知。

### 5.3 DCT 在训练 vs 推理中的角色

| | 训练 | 推理 |
|:---|:---|:---|
| **Encode（action → token）** | ✅ 训练数据中的 action 经 DCT+量化+BPE → token，作为训练目标 | ❌ 不需要 |
| **Decode（token → action）** | ❌ 不需要 | ✅ 模型自回归生成的 token → BPE decode → IDCT → 最终 action |

DCT 在训练时只做**编码**（把 ground-truth action 变成 token 标签），在推理时只做**解码**（把模型生成的 token 变回 action）。两个方向的数学运算是对称的。

---

## 六、一句话总结

> **DCT 是 JPEG 压缩图片、MP3 压缩音频、FAST 压缩动作的共同数学基础。它把信号从"每个时刻的值"变成"每种频率的强度"——因为自然信号的 90% 信息挤在前 20% 的频率里，所以丢掉高频成分几乎不影响质量，却能换来 5-30 倍的压缩。**
