# BPE（字节对编码）详解：从 LLM 分词到机器人动作压缩

> **主题**：Byte Pair Encoding——GPT 的分词算法，如何被 FAST 用来压缩动作
> **用途**：理解 FAST tokenizer 中 BPE 的工作原理
> **关联文档**：[π₀-FAST 论文导读](./fast_paper_guide.md) · [DCT 详解](./dct_guide.md)

---

## 读之前先搞清楚

### BPE 在做什么？

BPE 回答一个简单的问题：**"这段序列里，哪些连续片段频繁一起出现？把它们合并成一个符号。"**

举个例子——假设你有一堆英文文本，统计后发现 "t" 和 "h" 几乎总是连着出现（"the", "this", "that"...）。BPE 会把 "t"+"h" 合并成 "th" 这个新符号。下一步，"th"+"e" 合并成 "the"。以此类推。

FAST 用 BPE 对 DCT 压缩后的频率系数序列做同样的事——发现"哪些系数组总是连在一起"，合并成 token。

> **小白理解**：BPE 像给一段文字发明缩写。"中华人民共和国"出现了 1000 次 → 太长了 → 发明缩写"中国"。下一步发现"中国"+"人"常常一起出现 → "中国人"。**LLM 用 BPE 是因为"the"比"t-h-e"更好学；FAST 用 BPE 是因为"常见运动模式"比"逐频率值"更好学。**

### 阅读本文需要的前置知识

| 概念 | 简单解释 |
|:---|:---|
| **Token（词元）** | LLM 处理的最小单位——不是字母，是"词片"。如 "playing" → ["play", "ing"] |
| **词汇表（Vocabulary）** | 所有 token 的集合——模型只能预测词表内的 token |
| **合并（Merge）** | BPE 的核心操作——把两个相邻符号换成一个新符号 |

## 一、BPE 的直觉理解

### 1.1 从最简单的例子开始

假设我们有一个极小的"语料库"——只包含三个动作序列（已简化为字母）：

```
序列 1: a b c d a b
序列 2: a b c a b d
序列 3: a b a b c d
```

BPE 的训练过程：

**第 0 轮**：初始词表 = 所有单个字符 {a, b, c, d}

统计所有相邻字符对的出现次数：

```
"a b": 出现了 6 次  ← 最高频！
"b c": 出现了 2 次
"c d": 出现了 2 次
"b a": 出现了 1 次
"d a": 出现了 1 次
"c a": 出现了 1 次
...
```

**第 1 轮**："a b" 出现了 6 次——最高频。合并为新的 token "ab"。

词表变为 {a, b, c, d, **ab**}

序列变为：
```
序列 1: ab c d ab
序列 2: ab c ab d
序列 3: ab ab c d
```

**第 2 轮**：重新统计：

```
"ab ab": 出现了 1 次
"ab c": 出现了 3 次  ← 现在最高频
"ab d": 出现了 1 次
"c d":  出现了 2 次
"c ab": 出现了 1 次
```

**第 2 轮合并**："ab c" 出现 3 次——合并为 "abc"。

词表变为 {a, b, c, d, ab, **abc**}

**继续合并**直到词表达到目标大小（如 1000 个 token），或没有频次 ≥ 2 的 pair。

> **关键洞察**：BPE 学习的是数据中**反复出现的模式**。在自然语言中是 "the", "ing", "tion"——在动作频域数据中是 "[2.9]", "[-1.8, -0.1]" 这种反复出现的频率组合。

## 二、BPE 的算法

### 2.1 训练（学习合并规则）

```
输入: 大量序列（每个序列是一维整数列表）+ 目标词表大小 V

1. 初始化词表 = 所有出现过的单独特号
2. 初始化每个序列为"字符级"表示
3. while 词表大小 < V:
     a. 统计所有相邻符号对的频次
     b. 找到频次最高的 pair (A, B)
     c. 如果没有 pair 频次 ≥ 2: break
     d. 在词表中添加新符号 "AB"
     e. 在所有序列中，把 "A B" 替换为 "AB"
4. 输出: 合并规则列表（按顺序）+ 最终词表
```

### 2.2 推理（用合并规则编码新序列）

```
输入: 新序列 + 训练好的合并规则

1. 初始化为"字符级"表示
2. 按训练时的顺序依次应用每条合并规则:
     for rule in merge_rules:
         在序列中找到所有 (A, B) 的位置
         替换为 "AB"
3. 输出: token 序列
```

**关键**：BPE 推理不重新统计频次——它严格按训练时学到的规则顺序来。这是为什么 BPE tokenizer 训好后可以独立分发（如 `physical-intelligence/fast` 在 HuggingFace 上）。

## 三、BPE 在 FAST 中的角色

### 3.1 输入是什么？

不是原始 action 值，也不是文字——是 DCT+量化后的**频率系数整数序列**。

```
DCT+量化后的序列: [12, -8, 3, 12, -8, 3, 0, 0, 12, -8, 3, ...]
                    └─────────┘                 └─────────┘
                    反复出现的模式              同样的模式再次出现
```

### 3.2 BPE 学到了什么——"动作词汇"

在 1M 条机器人 action chunk 上训练 BPE 后，学到的典型 token：

| Token ID | 内容 | 物理含义 |
|:---:|:---|:---|
| 42 | `[12]` | 单一常见 DCT 系数值 |
| 156 | `[-8, 3]` | "递减趋势 + 微小正向加速度"模式 |
| 387 | `[12, -8, 3]` | "均值偏正 → 快速递减 → 微反弹"的完整运动片段 |
| 512 | `[0, 0, 0, 0, 0]` | 连续 5 个零（高频被量化归零，极其常见） |

> **关键洞察**：BPE 学到的不是"自然语言词汇"（名词、动词、形容词），而是**力学原语**（加速模式、减速模式、匀速模式、反弹模式）。这就像 Labanotation（拉班舞谱）把舞蹈分解为基本动作符号——FAST 的 BPE 自动发现了机器人运动的"基本动作符号"。

### 3.3 为什么在 DCT 之后用 BPE？

DCT 解决了"时间冗余"——相邻步相似 → 低频系数。但不同维度、不同 chunk 之间仍然有冗余——不同任务中反复出现的运动模式。

BPE 解决的就是这个"跨 chunk 的模式冗余"：

```
DCT 前: 跨 chunk 的模式被埋在原始数值里，难以发现
DCT 后: 模式变为反复出现的频率系数序列，BPE 可以直接统计合并
```

**DCT 处理 chunk 内的冗余（时间），BPE 处理 chunk 间的冗余（模式）。** 两者分工明确。

## 四、BPE 在训练 vs 推理中的角色

### 训练时：Encode（action → token）

```
ground-truth action chunk (H=50, D=32)
    │
    ▼ DCT → 量化 → Flatten
一维整数序列: [12, -8, 3, 0, 0, ...]
    │
    ▼ BPE encode（应用合并规则）
token 序列: [42, 156, 512, ...]   ← 30-60 个 token
    │
    ▼ 映射到 PaliGemma 词表（FAST token → PaliGemma vocab ID）
PaliGemma token IDs: [256890, 257004, 257360, ...]
    │
    ▼ 拼接在 postfix 中: "Action: [tok_1] [tok_2] ... [tok_N] |" + EOS
    │
    ▼ VLA 训练目标: 给定 prefix + 之前的 token → 预测下一个 token
```

### 推理时：Decode（token → action）

```
模型自回归生成的 PaliGemma token IDs
    │
    ▼ 从 PaliGemma 词表映射回 FAST token
FAST token 序列: [42, 156, 512, ...]
    │
    ▼ BPE decode（按词汇表展开 token → 整数序列）
整数序列: [12, -8, 3, 0, 0, ...]
    │
    ▼ Unflatten → 补零 → IDCT
最终 action chunk (H=32, D=32)
```

## 五、为什么是 BPE？——和其他方法的对比

| | BPE | 固定 binning | Huffman 编码 | 神经网络 tokenizer (FSQ/VQ-VAE) |
|:---|:---|:---|:---|:---|
| **压缩原理** | 合并高频 pair | 每维独立离散化 | 变长编码（高频→短码） | 学习连续→离散映射 |
| **是否学习** | ✅ 从数据学习 | ❌ 人工设定 | ❌ 仅基于频次 | ✅ 端到端学习 |
| **序列长度压缩** | ✅ 显著 | ❌ 反而膨胀 | ✅ 但压缩比较低 | ✅ 可学习压缩率 |
| **跨数据泛化** | ✅ 词汇表固定 | ✅ 规则固定 | ❌ 频次表依赖于数据 | ❌ tokenizer 与数据耦合 |
| **计算开销** | 极低（查表） | 极低 | 低（查表） | 高（需神经网络前向） |
| **实现复杂度** | 低 | 极低 | 中 | 高 |

**FAST 选 BPE 的三个理由**：

1. **轻量**：BPE 推理只是查表+替换，不增加推理延迟——这对机器人实时控制至关重要
2. **泛化**：BPE 词表在 1M 条数据上学好后固定，新任务不需要重新训练 tokenizer。FAST 发布了通用 tokenizer（`physical-intelligence/fast`），社区直接下载使用
3. **和 LLM 生态兼容**：BPE 是 LLM 的标准分词算法——FAST 可以复用整个 LLM 的 tokenizer 基础设施（HuggingFace `AutoProcessor` 等）

> **小白理解**：BPE 像一个"动作速记系统"。一个篮球教练不需要每次喊"右脚向前半步-左手上举-手腕前压"，他直接喊"挑篮"。篮球队员听到"挑篮"就知道是哪一组动作。**BPE 就是自动从海量比赛录像中发明这种"速记符号"。**

---

## 六、一句话总结

> **BPE 从数据中自动发现反复出现的模式，将其合并为 token——在自然语言中是 "the" 和 "ing"，在 FAST 中是 "加速-减速-反弹" 等力学原语。它接在 DCT 后面，DCT 压缩时间冗余，BPE 压缩跨 chunk 的模式冗余——两者分工，让 1600 个浮点数变成 30-60 个 token。**
