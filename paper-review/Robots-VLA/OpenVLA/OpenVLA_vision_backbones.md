# OpenVLA 视觉编码器深度解读：SigLIP 与 DINOv2

> 本文档详细介绍 OpenVLA 使用的两个视觉编码器——SigLIP 和 DINOv2。阅读本文后你将理解：它们各自怎么训练的、学到了什么特征、为什么两者融合比单独使用更好。主文档见 [OpenVLA 论文导读](./OpenVLA_paper_guide.md)。

---

## 读之前先搞清楚

### 为什么机器人需要两种视觉特征？

机器人看一张图，需要回答两个完全不同的问题：

| 问题 | 需要的能力 | 典型例子 |
|:---|:---|:---|
| **这是什么？** | 语义理解 | "红色杯子"、"金属罐"、"茄子" |
| **它在哪？什么姿态？** | 空间理解 | "杯子在桌子右边 15cm，把手朝左"、"罐子平躺，开口朝上" |

传统视觉模型很难同时做好这两件事。**语义理解好**的模型（如 CLIP、SigLIP）通常在空间精度上不行——它们能把"红色杯子"和"蓝色杯子"区分开，但说不清杯子离机械臂末端有多远。**空间理解好**的模型（如 DINOv2）能精确描述物体边界和位置，但不知道那个椭球形物体是"茄子"还是"紫甘蓝"。

> **小白理解**：这就像请两个人描述同一张桌子上的东西。语文老师（SigLIP）说"桌上有一个红色马克杯、一包薯片、一把剪刀"。几何老师（DINOv2）说"桌子左上方有一个圆柱体（半径 4cm、高 12cm、离桌面边缘 8cm）、旁边有一个长方体（20×15×5cm）"。你单独听谁的都不够——必须两人配合，你才知道"那个圆柱体就是红色马克杯，位置在桌子左上方 8cm 处"。

### 前置知识

| 概念 | 简单解释 |
|:---|:---|
| **ViT（Vision Transformer）** | 把图片切成小块（patch），像处理文字一样用 Transformer 处理图片 |
| **对比学习（Contrastive Learning）** | 让匹配的图文对在向量空间中靠近，不匹配的远离 |
| **自监督学习** | 不靠人工标注，让模型自己从数据中找规律（如判断两张图是不是同一张的裁剪） |
| **Patch Embedding** | ViT 把一张图切成 N 个小方块，每块变成一个向量 |

## 一、SigLIP：用 Sigmoid 损失做图文对齐

### 1.1 动机：CLIP 的问题在哪？

CLIP（Radford et al., 2021）是对比学习的代表作：用 4 亿**图文对**训练。注意"图文对"这个词——训练数据不是一堆图，也不是一堆文字，而是 **4 亿条 `(图片, 对应描述文字)` 的配对数据**，全部从互联网自动爬取（图片的 alt-text 当描述）。

**一个 batch 长什么样？** 假设 batch size B=4，一个 batch 里同时有：

```
图片:  🐱   🐶   ☕   🚗
       │    │    │    │
文本: "猫" "狗" "咖啡" "汽车"
```

4 张图 + 4 条文本，一一配对。正确配对是**对角线**上的：🐱↔"猫"、🐶↔"狗"、☕↔"咖啡"、🚗↔"汽车"。其余 12 个交叉组合（🐱↔"狗"、🐱↔"咖啡"……）全部是**错误配对**。

然后 CLIP 的损失函数做的事是：**让正确配对的相似度尽量高，同时让错误配对的相似度尽量低。** 它在整个 batch 上做 Softmax——每张图跟 batch 里所有文本比一遍：

$$\mathcal{L}_{\text{CLIP}} = -\frac{1}{2B}\sum_{i=1}^{B} \left[ \log\frac{\exp(s_{ii}/\tau)}{\sum_{j}\exp(s_{ij}/\tau)} + \log\frac{\exp(s_{ii}/\tau)}{\sum_{j}\exp(s_{ji}/\tau)} \right]$$

第一项：第 $i$ 张图在所有 $B$ 条文本中找到自己那条的概率。第二项：第 $i$ 条文本在所有 $B$ 张图中找到自己那张的概率。两者取平均。

**为什么 batch size 越大越好？** Softmax 的分母要对整个 batch 的所有**错误配对**求和。batch 越大，错误配对越多，"蒙对"越难——模型被迫学得更精细。但代价是显存放不下（B=32768 是 CLIP 原文的典型设置，需要几百张 GPU）。

> **小白理解**：CLIP 的 batch 不是"从图片里截出来的方块"（那是 DINOv2 的训练方式），而是**从互联网同时抓来的图片和文字**。就像一个老师同时拿出 4 张照片和 4 条说明文字，问模型："第一张照片配哪条说明？第二张配哪条？……"模型必须把对角线上的正确配对全找出来。batch=4 时，猜对的概率是 1/4——太简单了；batch=32768 时，猜对概率是 1/32768——难得多，但逼着模型学到了真正的图文对应关系。**这就是为什么 CLIP 训练需要几百张 GPU——不是模型大，是 batch 要足够大才能提供足够多的"错误配对"来训练区分能力。**

### 1.2 SigLIP 的解决方案：把 Softmax 换成 Sigmoid

SigLIP（Zhai et al., 2023）的核心创新非常简单：**把 batch 级别的 Softmax 对比损失，换成逐对的 Sigmoid 二分类损失**。

$$\mathcal{L}_{\text{SigLIP}} = -\frac{1}{|B|}\sum_{i=1}^{|B|} \left[ \log \sigma(s_{ii} + b) + \sum_{j \neq i} \log(1 - \sigma(s_{ij} + b)) \right]$$

其中 $\sigma(x) = 1/(1+e^{-x})$ 是 sigmoid 函数，$b$ 是可学习的偏置。

**两者的本质区别**：

| | CLIP (Softmax) | SigLIP (Sigmoid) |
|:---|:---|:---|
| **归一化范围** | 整个 batch（全局） | 逐对（局部） |
| **batch 内依赖** | 强依赖——一个负样本的分数变高会压低所有其他对的概率 | 无依赖——每对图文独立判断"是否匹配" |
| **batch size 敏感度** | 高度敏感——batch 越大越好 | 不敏感——小 batch 也能训练 |
| **计算效率** | 需要大 batch → 多 GPU | 小 batch 也能工作 → 更省资源 |

> **小白理解**：CLIP 是"把所有候选人放一起比，排出第一名"——候选人越多，排出来的第一名越可靠。SigLIP 是"逐个面试，对每个候选人独立判断合格/不合格"——不需要把所有候选人凑齐，来一个面一个。**这意味着 SigLIP 可以用更小的 batch、更少的 GPU 训练出同等质量的特征。**

### 1.3 SigLIP 学到了什么？

SigLIP 在 40 亿图文对（WebLI 数据集）上训练后，图像编码器学会了：
- **类别级别的语义**：区分"猫"vs"狗"、"红色"vs"蓝色"
- **细粒度属性**：区分"马克杯"vs"玻璃杯"、"跑车"vs"SUV"
- **文字-图像对齐**：将"a red cup on a wooden table"的文本向量推向对应图片的图像向量

但对机器人操作来说，SigLIP 有一个致命短板——**它不擅长精确的空间定位**。它能告诉你图里有"杯子"，但很难告诉你杯子在像素坐标 (342, 518) 处，朝向 45°。

> **小白理解**：SigLIP 像一位艺术品鉴定师——看一眼就知道"这是一幅莫奈的睡莲，创作于 1906 年"。但如果你问他"画中那片荷叶离画框左边多少厘米"，他答不上来。他就是不关心精确的空间度量。

#### 🔢 具体数字例子：SigLIP 的图文匹配判断

**条件**：batch 中有 3 张图（猫、狗、杯子）+ 3 条文本（"a cat"、"a dog"、"a cup"）。

每对图文计算余弦相似度：

| 相似度 $s_{ij}$ | "a cat" | "a dog" | "a cup" |
|:---|:---:|:---:|:---:|
| 🐱 猫图 | **0.85** | 0.12 | -0.05 |
| 🐶 狗图 | 0.10 | **0.78** | -0.02 |
| ☕ 杯图 | -0.03 | -0.01 | **0.92** |

SigLIP 逐对判断：
- (猫图, "a cat")：$\sigma(0.85+b) \approx 0.92$ → 匹配 ✅
- (猫图, "a dog")：$\sigma(0.12+b) \approx 0.34$ → 不匹配
- (杯图, "a cup")：$\sigma(0.92+b) \approx 0.95$ → 匹配 ✅
- (杯图, "a dog")：$\sigma(-0.02+b) \approx 0.08$ → 不匹配 ✅

> **关键理解**：每对判断都是独立的。(杯图, "a dog") 被正确判定为不匹配，这完全不影响 (狗图, "a dog") 是否匹配。**而在 CLIP 中，所有负样本共享同一个概率空间——一个假阳性会"挤占"其他正样本的概率。**

## 二、DINOv2：不需标签，自己学会"看"世界

### 2.1 动机：标注太贵了，能不能不靠标签？

SigLIP 需要 40 亿图文对——虽然图文对可以从互联网自动爬取（alt-text），但仍有局限：互联网图片偏向"好看"的（风景、美食、自拍），机器人的真实操作场景（杂乱的工作台、金属零件、各种角度的机械臂）很少出现在互联网图文中。

DINOv2（Oquab et al., 2023）走了一条完全不同的路：**自监督学习**——不给模型任何文字标签，让它从海量无标注图片中自己学会"看懂"图像。

> **小白理解**：SigLIP 的学习方式像"看图识字"——有人告诉你"这是猫"、"那是狗"，你逐渐学会。DINOv2 的学习方式像小孩自己翻图画书——没人告诉你叫什么，但翻多了你自然会发现"这个毛茸茸的四脚动物"和"那个光滑的圆柱体"不是同一种东西。**自监督学习的好处是：不受标注数据类型的限制，什么图都能学——包括机器人工作台上的杂乱场景。**

### 2.2 训练方式：学生-教师蒸馏 + 图像级对比

> ⚠️ **与 CLIP 的关键区别**：CLIP 的 batch 里是**图文对**（一张图 + 一句描述文字），DINOv2 的 batch 里**只有图**——每张图随机裁剪两次，产生两个视角的"孪生图"。模型的任务是让这两个裁剪产生相似的特征。

DINOv2 的训练核心是 **学生-教师自蒸馏**（student-teacher self-distillation）：

```
                    同一张图的两个随机裁剪
                    ┌─────────┼─────────┐
                    ▼                   ▼
              裁剪 A (全局)        裁剪 B (局部)
                    │                   │
                    ▼                   ▼
              学生网络             教师网络
           (正常 ViT)      (ViT + EMA 更新)
                    │                   │
                    ▼                   ▼
            特征 f_student       特征 f_teacher
                    │                   │
                    └─────────┬─────────┘
                              ▼
                    让 f_student 尽量接近 f_teacher
                    （用 Sinkhorn-Knopp 做中心化）
```

关键设计：
1. **同一张图的两个裁剪**作为"正样本对"——迫使模型学会：从不同角度、不同尺度看同一个物体，输出的特征应该一致
2. **教师网络不通过梯度更新**，而是通过学生权重的指数移动平均（EMA）更新——教师更稳定，给学生提供更好的"学习目标"
3. **Sinkhorn-Knopp 归一化**：防止模型坍缩（所有输出都一样），保证 batch 内不同图像的特征均匀分布

> **小白理解**：这就像师傅带学徒。师傅（教师网络）已经有比较稳定的"眼光"了，他看一张桌子说"这有个圆柱体在坐标 (0.3, 0.7) 位置"。学徒（学生网络）只看到了桌子的另一角，但他的任务就是推测出和师傅一样的结论。**关键在"同一张图的两个裁剪"——这让模型学会：不管你从哪个角度看，同一个物体的特征表征应该不变。这就是为什么 DINOv2 的空间理解特别好。**

### 2.3 DINOv2 学到了什么？

DINOv2 在 1.42 亿张精心筛选的图片（LVD-142M 数据集）上训练后，表现出惊人的空间理解能力：

- **像素级的语义分割**：不需要任何分割标注，DINOv2 的特征图直接就能区分不同物体——同一物体的 patch 特征彼此接近，不同物体的 patch 特征彼此远离
- **细粒度对应**：两张不同角度拍的同一场景，DINOv2 能自动找到对应的像素点
- **深度估计**：从 DINOv2 的特征中可以线性读出场景的深度信息

> **小白理解**：DINOv2 像一位从不看文字标签、纯粹靠"看"来理解世界的观察者。你给它看 100 张有杯子的图，它不会说"这是杯子"，但它知道这些图中都有同一个"圆柱形+有把手"的pattern，而且能精确标出这个 pattern 在每张图的什么位置。**这对机器人抓取来说价值巨大——我不需要知道"这是什么品牌的水杯"，我需要知道"这个可抓握的圆柱体在哪、什么朝向"。**

#### 🔢 具体数字例子：DINOv2 如何"自动做分割"

**条件**：一张工作台图片（256 个 patch），上面有茄子、碗、机械臂。

DINOv2 输出 256 个 patch 特征，每个 768 维。计算每对 patch 特征的余弦相似度：

```
相似度矩阵（部分）：
              patch_34  patch_35  patch_36  ...
              (茄子上)  (茄子上)  (碗边缘)
patch_34      1.00      0.94      0.12      ← 茄子内部：高度相似！
patch_35      0.94      1.00      0.08
patch_36      0.12      0.08      1.00      ← 碗边缘与茄子：不相似
```

同一个茄子的不同 patch（34, 35）之间相似度 0.94；茄子和碗的 patch（34, 36）之间相似度只有 0.12。**不需要任何标注，DINOv2 就自动学会了把"同一个物体"的 patch 聚在一起。**

> **关键理解**：DINOv2 的"分割能力"不是训练时有人教它"这是茄子那里是碗"，而是从"同一张图的两个裁剪应该是同一场景"这个约束中自然涌现的。**自监督学习的设计哲学在此体现得淋漓尽致——给模型一个巧妙的"自监督任务"（判断两个裁剪是否是同一张图），模型自己就会学到比你预期更多的能力。**

## 三、为什么两者融合更好？

### 3.1 各自的长处和短板

| | SigLIP | DINOv2 |
|:---|:---|:---|
| **擅长** | 语义识别：这是茄子、那是碗 | 空间定位：茄子在第 3 行第 5 列的 patch 区域 |
| **不擅长** | 精确空间定位——"茄子在哪" | 物体类别——"这个椭球是茄子还是紫甘蓝" |
| **训练数据** | 40 亿图文对（互联网） | 1.42 亿图片（纯图像） |
| **特征维度** | 1024 维 | 768 维（ViT-L） |

### 3.2 融合方式：通道拼接（Channel-wise Concatenation）

OpenVLA 的做法非常简单——把 SigLIP 和 DINOv2 的输出在**通道维度**拼接：

```
图片 (224×224)
    │
    ├──→ SigLIP → (256 patches, 1024 维)
    │
    └──→ DINOv2 → (256 patches, 768 维)
                    │
                    ▼
             通道拼接 → (256 patches, 1024+768=1792 维)
                    │
                    ▼
              2 层 MLP 投影 → (256 patches, 4096 维) → 送入 Llama 2
```

每个图像 patch 现在同时携带了两种信息：SigLIP 告诉它"这部分属于茄子"，DINOv2 告诉它"这个茄子在第 4 行第 7 列的 patch 中，与邻接的碗有明显边界"。

### 3.3 为什么不做更复杂的融合（如交叉注意力）？

论文选择了最简单的拼接而非交叉注意力等复杂融合，原因有二：
1. **简单有效**：拼接已经足够好，消融实验中融合比单一编码器有显著提升，更复杂的融合未必带来额外增益
2. **计算效率**：拼接是 $O(1)$ 的操作，交叉注意力是 $O(n^2)$——对于 256 个 patch，额外开销不值得

> **小白理解**：就像拼图。你不用让 SigLIP 和 DINOv2 开会讨论"这个 patch 到底是茄子还是碗"——直接把两张半透明的信息图叠在一起就够了。SigLIP 告诉你"这块是紫色的"，DINOv2 告诉你"这块是连续的椭圆形区域"，叠在一起你自然知道"这是一个紫色椭球，大概率是茄子"。

## 四、对自动驾驶/机器人视觉的启示

OpenVLA 的 SigLIP + DINOv2 融合方案对自动驾驶也有直接启发：

| OpenVLA 做法 | 自动驾驶类比 |
|:---|:---|
| SigLIP 提供语义（"这是行人"） | 目标检测/分类头 |
| DINOv2 提供空间（"行人在车前方 12.5m，横向偏移 0.3m"） | BEV 特征/Occupancy 网络 |
| 通道拼接 | 多模态融合中的 early fusion 策略 |

> **核心启示**：语义理解和空间理解需要不同的训练范式和数据分布。**试图用一个模型同时做好这两件事很难，但用两个互补模型做"通道拼接"这种极简融合，往往比精心设计的复杂融合更有效。** 这个设计哲学在自动驾驶的多模态感知（摄像头+LiDAR 融合）中同样适用。
