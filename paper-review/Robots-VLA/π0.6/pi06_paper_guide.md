## 读之前先搞清楚

### 这篇论文要解决什么问题？

π₀ 和 π₀.₅ 证明了 VLA 能做复杂长程任务（叠衣、收桌、新家打扫），π*0.6 要解决一个更深层的问题：**如何让 VLA 不只"能做"，而是"做得又快又好又稳"——达到可部署的商用可靠性。**

所有之前的 VLA（包括 π₀ 和 π₀.₅）都是用**模仿学习（Imitation Learning）**训练的——看人类示范，然后模仿。这个方法有一个数学上注定的天花板：

```
模仿学习为什么永远做不到 100% 成功率：

训练数据分布：人类示范中的状态序列
          t=0    t=1    t=2    t=3    t=4
人类：    拿起杯 → 移动 → 对准 → 放入 → 松手     ← 完美轨迹
         (s₀,a₀) (s₁,a₁) (s₂,a₂) (s₃,a₃) (s₄,a₄)

机器人推理时（有一点点误差）：
         t=0    t=1       t=2            t=3
机器人： 拿起杯 → 移动偏了 → 杯子歪了 → 撞到微波炉门
         (s₀,a₀) (s₁',a₁') (s₂',a₂')    (s₃',a₃')
                  ↑ 小偏差  ↑ 状态偏离训练分布 ↑ 更大偏差 → 崩溃
                  
关键问题：s₁'（偏了的状态）在训练数据中不存在！
→ 模型不知道在 s₁' 这个"异常状态"下该怎么办
→ 只能按照训练数据中最近的"正常状态"来输出 action
→ 但正常状态的 action 在异常状态下可能让情况更糟
→ 这就是 Compounding Errors（复合误差）：小错 → 大错 → 失败
```

这就是为什么模仿学习的模型"有时成功、有时失败"——当机器人完美复刻人类轨迹时能成功，但一旦出现微小偏差（必然出现的），就会逐步偏离训练分布，最终失败。

> **小白理解**：模仿学习就像"背菜谱做菜"——你看大厨的示范，他说"大火炒 30 秒然后关火"。但你家的火力和大厨的不一样（环境偏差），30 秒后菜已经糊了（进入异常状态）。菜谱里没有教"糊了怎么办"，所以你只能继续照菜谱做，结果越来越糟。RECAP 的答案是：**让你自己反复做这道菜，糊了之后自己摸索怎么补救，从失败中学习。**

### π₀ vs π0.6：一张表看懂核心区别

π₀ 是 Physical Intelligence 的第一代机器人基础模型（2024.10），证明了 VLA 能做复杂长程任务。π0.6 / π*0.6 不是 π₀ 的小改版，而是一次**训练范式的根本转变**——从"看示范模仿"进化为"从自身经验中学习"。

| 维度 | π₀ | π0.6 / π*0.6 |
|:---|:---|:---|
| **训练范式** | 模仿学习（IL）——看人类示范→监督学习模仿 | **RECAP**：Offline RL → Coaching → Online RL，三步渐进 |
| **数据策略** | 只用成功示范（"好数据"），失败数据丢弃 | **全部保留**：好数据+坏数据+矫正数据，每条标注 advantage（好坏标签） |
| **错误处理** | 没见过异常状态 → compounding errors → 崩溃 | 从坏数据中学会"避免什么" + 人类矫正教"如何补救" + 自主探索验证 |
| **模型架构** | PaliGemma ~3B VLM + Flow Matching Action Expert（300M） | **~5B VLM** + Flow Matching Action Expert + **Advantage-Conditioned Policy** |
| **Prompt 能力** | 语言指令（"叠这件衣服"） | **异构 prompt**：语言 + quality（做多好）+ speed（做多快）+ control mode |
| **能力定位** | 通用基础模型（foundation model），可 zero-shot 跨任务 | **Per-task specialist**：每个任务独立 RECAP 训练，但该任务上达到商用可靠性 |
| **可靠性** | ~50-70% 成功率（模仿学习固有天花板） | **>90% 成功率**，吞吐量 ×2，失败率 ÷2 |
| **训练流程** | Pre-train（10,000h 多机器人数据）→ fine-tune（几小时高质量数据） | Offline RL pre-train → Coaching（人类介入矫正）→ Online RL（自主探索改进） |

> **小白理解**：π₀ 像一个"看过所有菜谱的厨师"——知道每道菜怎么做，但第一次上手时手忙脚乱（成功率 ~65%）。π*0.6 像一个"做了 1000 遍咖啡的老师傅"——不仅知道怎么做，还踩过所有坑：磨豆太粗怎么办、压粉不均怎么补救、打奶泡过烫怎么调整。**π₀ 给你的是"知识"，π*0.6 给你的是"经验"——这就是模仿学习 vs 强化学习的本质区别。**

### 读懂这篇论文需要的前置知识

| 概念 | 简单解释 |
|:---|:---|
| **Imitation Learning（IL）/ Behavioral Cloning** | 看人类示范 → 监督学习模仿——只能学会"在训练见过的状态下怎么做" |
| **Compounding Errors** | 小误差导致状态偏离训练分布 → 模型不知道该怎么做 → 更大误差 → 失败 |
| **Reinforcement Learning（RL）** | Agent 自己执行动作 → 环境给 reward → 从 reward 信号中学习"什么好什么坏" |
| **Credit Assignment** | 回溯"整段序列中哪一步导致了最终的成功/失败"——RL 核心难题 |
| **Value Function（价值函数）** | V(s) = 从状态 s 出发，按当前策略能获得的期望累积 reward |
| **Advantage（优势函数）** | A(s,a) = Q(s,a) - V(s)——这个 action 比平均水平好多少，正 = 好 action |
| **Offline RL** | 从历史固定数据集中学 RL，不需要实时环境交互 |
| **Online RL** | Agent 实时与环境交互，探索→收集数据→更新策略→再探索 |

## 一、RECAP 的解决思路

RECAP = **R**L with **E**xperience & **C**orrections via **A**dvantage-conditioned **P**olicies

核心 idea：**把 RL 的三大组件——(1) 从历史数据中学好坏（Offline RL pre-training）、(2) 人类在关键时刻矫正（Coaching with corrections）、(3) 机器人自主探索+从 reward 中改进（Online RL）——整合成一个三步流程，最终得到 Advantage-Conditioned Policy：输入画面+语言+期望的 advantage 值，输出对应的 action。**

```
传统模仿学习（IL）的局限：
  数据：只有人类成功的示范（"好"数据）
  问题：没见过"坏状态"，不知道如何补救
  结果：成功率 ~50-70%，永远无法接近 100%

RECAP 的数据策略：
  ┌─────────────────────────────────────────────────────────┐
  │ ① 保留所有历史数据（含失败和低质量）                      │
  │    标注每个 action 的 advantage（好/坏）                  │
  │    训练 advantage-conditioned policy                     │
  │    → 模型学会了"这种 action 是好的，那种是坏的"            │
  ├─────────────────────────────────────────────────────────┤
  │ ② 人类只在关键时刻介入（Coaching）                        │
  │    机器人执行 → 犯错 → 人类遥操作接管 → 示范正确的补救     │
  │    这段矫正数据标注为 advantage = +1.0                    │
  │    → 针对性提供"在异常状态下应该怎么做"的数据              │
  ├─────────────────────────────────────────────────────────┤
  │ ③ 机器人自主探索（Online RL）                             │
  │    执行完整 episode → 根据最终结果给 reward                │
  │    Value function 回溯 credit assignment                 │
  │    → 从无数次失败中自动发现"怎么做更好"                    │
  └─────────────────────────────────────────────────────────┘
```

> **小白理解**：三种学习方式的类比。模仿学习 = 只看教学视频（只看到对的，没见过错的）。RECAP Offline RL = 看了大量"对的和错的"对比视频，知道什么好什么坏。RECAP Coaching = 教练在你犯错时喊停，手把手教你正确做法。RECAP Online RL = 你自己反复练习，每次练完复盘"刚才哪一步可以做得更好"。三者结合 = 最佳学习效果。

## 二、RECAP 三步详解

### 第 1 步：Offline RL Pre-training —— "从历史数据中学好坏"

**这一步在整个流程里的作用**：用所有可用的历史数据（不只是成功示范，也包括失败和低质量数据），训练一个能"判断好坏"的基础模型。这是 RECAP 和传统 imitation learning 最本质的区别。

- **输入**：所有历史 robot 数据（D = {observations, actions, rewards/success_labels}），包括：
  - 高质量人类示范（success=1）
  - 低质量/失败的自主执行 episode（success=0 或 partial）
  - 人类矫正片段（coaching corrections）

- **操作**：

  > **总览**：历史数据 → 训练 Value Function（预测成功概率）→ 计算每个 action 的 advantage → 训练 advantage-conditioned policy
  >
  > ```
  > 历史数据集 D = {(o₁,a₁,r₁), (o₂,a₂,r₂), ..., (o_T,a_T,r_T)}
  > 
  >         ┌──────────────────┐
  >         │ ① 训练 Value Function V_φ  │
  >         │   V_φ(o_t) = 预测从 o_t 开始到 episode 结束的期望累计 reward │
  >         │   训练目标：min Σ(V_φ(o_t) - R_t)²          │
  >         │   其中 R_t = Σ_{k=t}^T γ^{k-t} r_k（实际的累计 reward）│
  >         └────────┬─────────┘
  >                  │
  >                  ▼
  >         ┌──────────────────┐
  >         │ ② 计算 Advantage A_t    │
  >         │   A_t = R_t - V_φ(o_t)               │
  >         │   A_t > 0 → 这个 action 比预期好（好 action！）  │
  >         │   A_t < 0 → 这个 action 比预期差（坏 action！）  │
  >         └────────┬─────────┘
  >                  │
  >                  ▼
  >         ┌──────────────────┐
  >         │ ③ 训练 Advantage-Conditioned Policy π_θ │
  >         │   输入: o_t + A_t（advantage 作为额外 condition）│
  >         │   输出: predicted action â_t          │
  >         │   训练目标：min Σ(a_t - â_t)²（所有数据都用）   │
  >         │   但模型通过 A_t 知道每个 action 的好坏！     │
  >         └──────────────────┘
  > ```

  **① Value Function V_φ**：这是一个神经网络（轻量 MLP head，挂在 VLM backbone 的输出上），它的任务是预测"从当前观测 o_t 出发，按当前策略执行，最终能得到多少累计 reward"。在 π*0.6 中，reward 就是任务的最终成功与否——成功了 reward=1，失败了 reward=0。Value function 输出一个 0~1 之间的数，表示"预期成功概率"。

  **② Advantage 计算**：Advantage A_t 衡量的是"在状态 o_t 下做了 action a_t，结果比预期好多少"。如果 A_t = +0.3，说明做了这个 action 后，最终的成功概率比之前预测的高了 30%——这是好 action。如果 A_t = -0.2，说明这个 action 让成功概率降低了 20%——这是坏 action。

  **③ Advantage-Conditioned Policy**：这是 RECAP 最精妙的设计。传统 RL 的做法是"只用好数据训练，丢掉坏数据"——但这样丢掉了"什么是坏的"的信息。RECAP 的做法是**保留所有数据，但把 advantage 作为额外 condition 输入 policy**。这样模型在训练时看到：
  - `(o_t, A=+0.8) → action`：高 advantage 时应该输出什么样的 action（好做法）
  - `(o_t, A=-0.5) → action`：低 advantage 时输出什么样的 action（坏做法，知道要避免）

  推理时，只需把 advantage 设为一个大正数（如 A=+1.0），模型就会从训练经验中选取最高优势的行为。

- **输出**：一个 base model π*0.6（offline RL 预训练版），已经比纯模仿学习的 π0.6 好了很多

> **小白理解**：传统模仿学习像老师只给你看"满分答卷"——你知道 100 分的答案长什么样，但不知道 60 分和 0 分的答案有什么不同。RECAP Offline RL 让你看了所有分数段的答卷，每份答卷旁边还标注了"这里扣了 10 分因为……"——你不仅知道什么是好的，还知道什么是坏的、为什么坏。这就是 advantage conditioning 的核心价值。

#### ❓ 常见疑问：为什么要保留"坏数据"？直接过滤掉不好吗？

保留坏数据训练 advantage-conditioned policy 有一个关键优势：**模型能从坏数据中学到"避免什么"，这是纯好数据训练做不到的。**

```
只用"好数据"训练的模型：
  在状态 s 下，模型只知道"应该输出 action a_good"
  当遇到从未见过的异常状态 s' 时，模型会"外推"——可能输出一个很差的 action
  因为它从未被教过"在 s' 这种状态下，什么 action 是坏的"

用好+坏数据训练 advantage-conditioned 的模型：
  在状态 s 下，模型见过：
    - (s, A=+1.0) → a_good（好的做法）
    - (s, A=-0.5) → a_bad（坏的做法）
  当遇到异常状态 s' 时：
    - 模型输入 (s', A=+1.0)，输出"在 s' 下最好的 action"
    - 即使 s' 不完全在训练分布中，模型也能区分"好方向"和"坏方向"
```

> **核心设计理由**：坏数据 = 额外的负样本监督信号。就像学开车——只看老司机开车的视频是不够的，你还需要看"车祸视频"来知道什么操作会导致事故。RECAP 的坏数据就是"车祸视频"，advantage label 就是"事故原因分析"。

### 第 2 步：Coaching with Corrections —— "人类在关键时刻介入"

**这一步在整个流程里的作用**：针对机器人最容易犯错的"关键点"，人类提供精准的矫正示范（通常只需 2-3 秒），让模型学会在这些易错状态下如何补救。

- **输入**：机器人用当前 policy 自主执行任务（观测+action 序列），人类遥操作设备就绪
- **操作**：

  > **总览**：机器人自主执行 → 人类观察 → 发现错误时接管 → 遥操作示范正确做法 → 矫正片段标注 advantage=+1.0 → 加入训练集
  >
  > ```
  > 一次 Coaching episode 的完整流程：
  > 
  > t=0:  机器人开始执行 "make espresso"
  > t=5:  机器人拿起咖啡手柄 ✓（正常，人类不介入）
  > t=10: 机器人试图装入手柄但角度偏了 ✗（预判会失败）
  >       → 人类按下"接管"按钮
  >       → 人类用遥操作调整角度，手柄正确装入
  >       → 这段矫正数据：(o₁₀, a_human₁₀) → advantage = +1.0
  >       → 标记：这是"在装手柄时角度偏了的状态下应该怎么做"的标准答案
  > t=12: 人类松开接管，机器人继续自主执行
  > t=20: 机器人按下萃取按钮 ✓
  > ...
  > episode 结束：成功！reward = +1.0
  > ```

  **① 为什么不直接让人类从头到尾示范？** 因为效率完全不同。一个 10 分钟的做咖啡任务，人类完完整示范需要 10 分钟。但 RECAP coaching 只需要在 2-3 个关键错误点各介入 2-3 秒，总共不到 30 秒。**更重要的是，矫正数据精确针对了机器人实际犯错的"异常状态"——这些状态在正常示范数据中根本不存在。**

  **② 矫正数据如何与 RL 结合？** 矫正数据被标注为 advantage=+1.0（最高优势），混合进 Offline RL 的训练集。Value function 和 policy 在更新时会"更重视"这些矫正数据——因为它们是针对 actual failure modes 的精准解决方案。

- **输出**：矫正数据片段，加入训练集后 policy 在这些关键点上的成功率大幅提升

> **小白理解**：传统示范像让你看一部完整的"如何做咖啡"教学视频（10 分钟）。RECAP coaching 像教练站在你旁边——你做着做着，教练突然说"停！你手柄角度不对，你看我怎么做"——然后只示范最关键的那 3 秒。这 3 秒比 10 分钟视频更有价值，因为它精准针对了你的薄弱环节。

### 第 3 步：Online RL on Robot —— "从自主经验中精进"

**这一步在整个流程里的作用**：机器人完全自主地反复执行任务，每次执行后根据最终结果获得 reward（成功=1，失败=0），Value function 回溯 credit assignment，policy 从成功和失败中不断改进。

- **输入**：当前 policy π_θ，Value function V_φ，机器人硬件，成功/失败判断器
- **操作**：

  > **总览**：机器人自主执行 N 个 episode → 收集 (o,a,r) 数据 → 更新 Value function → 重新计算 advantage → 更新 policy → 重复
  >
  > ```
  > Online RL 一次迭代的完整流程：
  > 
  > ① 数据收集（用当前 policy）：
  >   for episode in 1..N:
  >     机器人自主执行任务
  >     记录所有 (o_t, a_t)
  >     episode 结束后根据结果给 reward：
  >       成功 → r_T = +1.0
  >       失败 → r_T = -1.0（或 0）
  >       部分成功 → r_T = 0.5（如叠好了一半）
  > 
  > ② Value Function 更新：
  >   用新收集的数据重新训练 V_φ
  >   现在 V_φ 不只基于历史数据，还基于机器人最新的自主经验
  >   V_φ 学得更准——因为它见过更多"机器人实际会犯的错"
  > 
  > ③ Advantage 重新计算：
  >   对每个 (o_t, a_t)，计算 A_t = R_t - V_φ(o_t)
  >   新 V_φ 更准确 → advantage 更准确地反映"哪个 action 导致了成功/失败"
  > 
  > ④ Policy 更新：
  >   用重新计算的 advantage 继续训练 advantage-conditioned policy
  >   模型收敛：π_θ 学会选择 A>0 的行为模式
  > 
  > ⑤ 回到 ①，用更新后的 policy 继续收集更好的数据
  >   （better policy → better data → better V_φ → better advantage → even better policy）
  > ```

  **① 为什么 Online RL 能突破 imitation learning 的天花板？** 因为机器人自主探索时会产生大量"imitation learning 数据中没有的状态"——这些就是之前导致 compounding errors 的异常状态。通过在这些异常状态上收集真实的 (s, a, r) 数据，Value function 学会准确地评估"在异常状态下做什么是好、什么是坏"，policy 随之学会如何在异常状态下自救。

  **② Credit Assignment 如何解决？** 这是 RL 在长程任务（如做咖啡 10 分钟）中的核心难题。如果 episode 失败了，是哪一步导致的？RECAP 用 Value function 的差分来回答：`A_t = V(o_{t+1}) - V(o_t)`（简化版本）。如果执行 action a_t 后，Value 从 0.6 跳到 0.75 → A_t = +0.15（好 action）。如果 Value 从 0.6 跌到 0.4 → A_t = -0.20（坏 action）。**Value function 的变化自动完成了 credit assignment——不需要人工标注"哪一步出的错"。**

- **输出**：最终的 π*0.6 policy，在目标任务上达到 >90% 成功率 + 2× 以上吞吐量提升

> **小白理解**：模仿学习 = 只看过一遍菜谱就考试。Coaching = 考试中有教练在关键步骤提醒。Online RL = 自己做了 1000 遍考试，每次做完后复盘"这次哪里扣分了"——第 500 遍时，你已经把所有可能的扣分点都踩过了，知道怎么避免。这就是 Online RL 的力量：**犯足够多的错，然后从每一个错误中学习。**

#### 🔢 具体数字例子：做咖啡任务中 Value function 的一步步变化

**条件设定**：π*0.6 执行"make espresso"，咖啡机、磨豆机、压粉器均已就位。

| 时间 | 机器人动作 | V(o_t) 变化 | Advantage | 说明 |
|:---|:---|:---:|:---:|:---|
| t=0 | (开始) | 0.30 → | — | 初始成功率预测 30% |
| t=5 | 拿起 portafilter | 0.30 → 0.45 | **+0.15** ✓ | 成功拿起了，预期提升 |
| t=10 | 装入手柄，角度偏了 | 0.45 → 0.25 | **-0.20** ✗ | 操作失误，预期下降 |
| t=12 | (人类矫正后) | 0.25 → 0.55 | **+0.30** ✓ | 矫正后恢复正轨 |
| t=15 | 按下研磨按钮 | 0.55 → 0.55 | 0.00 | 按钮操作无影响 |
| t=20 | 压粉过轻 | 0.55 → 0.35 | **-0.20** ✗ | 压粉不够，萃取会失败 |
| ... | ... | ... | ... | ... |
| t=100 | 完成萃取，咖啡出品 | 0.80 → 1.00 | **+0.20** ✓ | 成功！ |

> **关键理解**：不需要人工标注"t=10 时装手柄角度偏了"——Value function 自动检测到了 V 的下降（0.45→0.25），自动标记为负 advantage。**这就是 Credit Assignment 的自动化实现。**

## 三、RECAP 训练流程 —— 从数据到专精模型的端到端管线

上面三步讲的是 RECAP 的**核心设计**（每一步在做什么）。这一节把它们串成完整的**训练管线**，说清楚数据如何在三个阶段之间流动、每个阶段的输入输出是什么、以及三阶段如何渐进式提升模型能力。

> **总览**：历史数据 → Offline RL Pre-training（学好坏）→ 部署初版 policy → Coaching（人类矫正关键错误）→ 更新 policy → Online RL（自主探索精进）→ 最终 π*0.6 specialist
>
> ```
> RECAP 完整训练管线：
> 
> ┌──────────────────────────────────────────────────────────────────┐
> │ Phase 1: Offline RL Pre-training（一次性，离线完成）             │
> │                                                                  │
> │  输入：所有历史数据 D（含成功+失败+矫正片段）                     │
> │        ↓                                                         │
> │  ① 训练 Value Function V_φ：输入 o_t → 输出期望成功率           │
> │        ↓                                                         │
> │  ② 对每条数据计算 Advantage：A_t = R_t - V_φ(o_t)               │
> │     A_t > 0 → 好 action；A_t < 0 → 坏 action                    │
> │        ↓                                                         │
> │  ③ 训练 Advantage-Conditioned Policy π_θ                        │
> │     输入 (o_t, A_t) → 输出 action，保留所有数据（好+坏）        │
> │     模型通过 A_t 标签学会区分"好 action"和"坏 action"          │
> │        ↓                                                         │
> │  输出：π0.6 base model（已比纯 IL 强 ~40%）                     │
> └──────────────────────────┬───────────────────────────────────────┘
>                            │
>                            ▼
> ┌──────────────────────────────────────────────────────────────────┐
> │ Phase 2: Coaching with Corrections（少量人类参与，可多轮迭代）   │
> │                                                                  │
> │  ① 将 Phase 1 的 policy 部署到真实机器人                         │
> │        ↓                                                         │
> │  ② 机器人自主执行任务，人类在旁观察                              │
> │        ↓                                                         │
> │  ③ 当机器人即将犯错时 → 人类接管 → 遥操作示范正确做法            │
> │     矫正片段标注 advantage = +1.0（最高优势）                    │
> │     每次介入只需 2-3 秒，一个任务仅需 2-3 个关键矫正点           │
> │        ↓                                                         │
> │  ④ 矫正数据加入训练集，重新训练 V_φ 和 π_θ                      │
> │        ↓                                                         │
> │  输出：policy 在关键易错点上的成功率大幅提升（+43%）              │
> └──────────────────────────┬───────────────────────────────────────┘
>                            │
>                            ▼
> ┌──────────────────────────────────────────────────────────────────┐
> │ Phase 3: Online RL on Robot（循环迭代，直到收敛）                │
> │                                                                  │
> │  ┌─────────────────────────────────────────────────────┐         │
> │  │ ① 部署当前 policy → 机器人自主执行 N 个 episode      │         │
> │  │        ↓                                            │         │
> │  │ ② 收集 (o_t, a_t, r_T) 数据                        │         │
> │  │    r_T = +1（成功）/ -1（失败）/ 0.5（部分成功）    │         │
> │  │        ↓                                            │         │
> │  │ ③ 用新数据更新 Value Function V_φ                  │         │
> │  │    V_φ 基于机器人最新自主经验 → 评估更准确           │         │
> │  │        ↓                                            │         │
> │  │ ④ 重新计算所有 advantage，更新 policy π_θ          │         │
> │  │    Better V_φ → Better advantage → Better policy    │         │
> │  │        ↓                                            │         │
> │  │ ⑤ 回到 ①，用更新后的 policy 收集更好的数据          │         │
> │  │    → 正反馈循环：better policy → better data → ... │         │
> │  └─────────────────────────────────────────────────────┘         │
> │        ↓                                                         │
> │  输出：最终 π*0.6 specialist（成功率 >90%，吞吐量 ×2）           │
> └──────────────────────────────────────────────────────────────────┘
> ```
>
> **三个阶段的分工与关系**：
>
> | 阶段 | 核心作用 | 数据来源 | 人力成本 | 效果贡献 |
> |:---|:---|:---|:---|:---|
> | **Offline RL** | 打基础：让模型从一开始就"知道好坏" | 全部历史数据（自动标注 advantage） | 零（纯离线计算） | +40% |
> | **Coaching** | 补短板：精准修补模型最容易犯错的关键点 | 人类遥操作矫正片段 | 极低（每次 2-3s × 几个关键点） | +43% |
> | **Online RL** | 自我进化：在真实环境中反复练习→从错误中学习 | 机器人自主执行数据（自动 reward） | 零（全自动，但需硬件时间） | +20% |
>
> > **小白理解**：RECAP 训练像一个运动员的三阶段成长路径。Offline RL = 看大量比赛录像（自己的+别人的，赢的+输的），总结"什么操作能赢、什么会输"。Coaching = 教练在训练中发现你挥拍姿势不对，亲自示范正确动作——精准高效。Online RL = 大量实战——每场打完复盘"这一球为什么得分/失分"，越打越好。**三阶段环环相扣：不看录像直接实战效率低，只实战没教练改不了根深蒂固的坏习惯，有教练有实战但不复盘提升有限。**

## 四、RECAP 推理流程 —— 训练好的模型如何在实际中运行

训练完成后，π*0.6 的推理和传统 IL 模型有本质区别——**多了 advantage conditioning 这一步**。

> **总览**：observation + language + advantage (固定+1.0) → VLM backbone + Action Expert → 单次前向传播 → action chunk → 机器人执行
>
> ```
> π*0.6 推理时的完整数据流：
> 
> ┌─────────────────────────────────────────────┐
> │ 推理输入（和训练时结构一致）                 │
> │                                             │
> │ · Camera Images（2-3 张 RGB）                │
> │ · Language（"make an espresso"）             │
> │ · Proprioceptive State（关节角度等）         │
> │ · ★ Advantage = +1.0（固定值，不随状态变！） │
> └────────────────────┬────────────────────────┘
>                      │
>                      ▼
>        ┌─────────────────────────┐
>        │  ~5B VLM Backbone       │
>        │  + Action Expert        │
>        │  + Flow Matching（推理  │
>        │    可减到 5 步）        │
>        └────────────┬────────────┘
>                     │
>                     ▼
>        ┌─────────────────────────┐
>        │  Action Chunk           │
>        │  H=50 步连续 action     │
>        │  （50Hz，覆盖 1 秒动作） │
>        └────────────┬────────────┘
>                     │
>                     ▼
>        ┌─────────────────────────┐
>        │  机器人执行 50 步 action │
>        │  执行完毕 → 重新推理     │
>        │  （receding horizon）   │
>        └─────────────────────────┘
> ```
>
> **Advantage Condition 在推理中的关键机制**：
>
> 推理时 advantage 被**固定设置为 +1.0（一个大正数）**，不随当前状态变化。这等于告诉模型："请输出训练数据中和最高 advantage 关联的那种 action。"
>
> 因为训练时模型见过来自同一状态的、不同 advantage 值的 action：
> - `(o_t, A=+1.0) → 最好的 action 做法`
> - `(o_t, A=+0.3) → 还行的 action 做法`
> - `(o_t, A=-0.5) → 糟糕的 action 做法（知道要避免）`
>
> 推理时输入 `A=+1.0`，模型自动选取最优行为模式。**不需要搜索、采样或优化——单次前向传播即可。**
>
> **推理与训练的关键区别**：
>
> | | 训练时 | 推理时 |
> |:---|:---|:---|
> | **Advantage 来源** | 从真实 rollout reward 计算（事后标注） | 人为固定 +1.0（"做最好的 action"） |
> | **Flow Matching 步数** | 10 步（训练稳定性） | 可减到 5 步（推理加速） |
> | **输出用途** | 计算 loss，反向传播更新参数 | 直接发给机器人执行 |
> | **是否需要 V_φ** | **需要**（用来计算 advantage 标签） | **不需要！** V_φ 仅训练用 |
> | **是否收集数据** | 收集（用于下一轮训练） | 不收集（纯推理模式） |
> | **计算量** | 高（梯度反向传播 + V_φ 训练） | 低（单次前向传播） |
>
> > **小白理解**：训练好的 π*0.6 像一个老司机——你只需说"去超市"（语言指令），他自动用最高水平来开（A=+1.0）。Advantage condition 在推理时就是"能力档位旋钮"——拧到最高档，模型自动输出训练中见过的最佳操作。**推理时非常简单：不需要 V_φ，不需要 RL，不需要探索——只有一个 forward pass，和普通 IL 模型推理速度一样快。**
>
> > ❓ **常见疑问：推理时固定 A=+1.0，如果模型在某状态下从未见过高 advantage 的 action 怎么办？**
> >
> > 这正是 RECAP 三阶段训练要解决的问题。Offline RL 保留了所有数据→模型见过各种 advantage 值。Coaching 提供了关键异常状态的 A=+1.0 示范。Online RL 通过自主探索填充了更多"高 advantage 行为路径"。**三阶段训练后，模型对绝大多数可能遇到的状态都有一条高 advantage 路径，推理时设 A=+1.0 就能稳定输出。**
> >
> > 如果仍然遇到全新状态（极端 OOD），模型会基于训练中学到的 advantage 方向"外推"——因为它理解"高 advantage 的行为方向"而非死记硬背。这是 advantage-conditioned policy 比纯 IL policy 泛化能力更强的根本原因。

## 六、核心创新点

| 创新点 | 具体内容 | 为什么重要 |
|:---|:---|:---|

## 九、局限性

| 局限性 | 为什么是局限 |
|:---|:---|
| **Per-task specialist** | 每个任务需要独立的 RECAP 训练（coaching+online RL），不能 one model for all |
| **仍需人类参与 coaching** | 完全自主 RL 探索效率不够，需要人类在关键错误时介入 |
| **Credit assignment 在极长任务中仍不完美** | 做咖啡 10 分钟的任务，Value function 的差分信号可能不够精确 |
| **Online RL 的硬件成本** | 需要机器人在真实环境中反复执行（可能数千 episode），对硬件可靠性要求极高 |
| **泛化到全新任务仍未知** | RECAP 训练的是 specialist，能否泛化到 related but different tasks 未验证 |

> **π*0.6 通过 RECAP（Offline RL → Coaching → Online RL）三步训练，让 VLA 从"看示范模仿"进化为"从自身经验中学习"——利用 Value Function 自动完成信用分配，利用 Advantage-Conditioned Policy 同时用好数据和坏数据，最终在叠衣、做咖啡、装纸箱三个真实长程任务上实现吞吐量翻倍、失败率减半，首次达到了可部署的商用可靠性水平。**
